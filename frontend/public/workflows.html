01 · Graph architecture

Evaluation LangGraph

The graph has a router, a step executor that loops through a selected plan, and a finalizer. Individual grading steps run inside the executor.

Implemented · not active in worker
S

START

Submission text, assignment rubric, topics, and course ID enter the graph.

1

Router node

Chooses a safe ordered plan and selects RAG or rubric feedback.

LLM request · deterministic fallback if plan is invalid
2

Execute plan

Dispatches the next step, advances the plan index, and loops until done.

This is the graph's loop
F

Finalize

Sets the final outcome to graded or flagged from the integrity result.

Steps dispatched inside Execute planRun in this dependency order →
01Integrity

Local duplicate and similarity lookup against assignment submissions.

No LLM call
02Coverage

Scores rubric evidence across submission chunks; may synthesize combined evidence.

One or more LLM calls
03Mastery & depth

Converts coverage into rubric points and a mastery band; rates conceptual depth.

Depth uses an LLM call
04Feedback

Retrieves relevant notes when available, then writes targeted feedback if needed.

RAG or rubric path · may call LLM
More planned steps? Return to Execute plan↻No steps left? Continue to Finalize
ⓘ

Why the old graph could hit rate limitsThe router, chunk scoring, optional synthesis, depth rating, and feedback can make several provider calls for one submission. The live worker uses one rubric grading request per attempt, followed by local integrity work.

The exact number of graph calls varies with submission length, whether a reference solution is supplied, and whether targeted feedback is needed.

429 · Waiting for AI capacity (45%)

Honor the provider cooldown, then retry the grading request. If the remaining quota reset is too far away or retries run out, mark it “Retry required.”

Grading→ 429 →Waiting↶ cooldownGrading retry

Other branches from grading

Unreadable text during preparation → “Needs teacher review.” Other service errors → “Retry required” for instructor retry.

↻Website status refresh: Student page polls the AI status endpoint every 3 seconds while the submission is pending or evaluating. Displayed percentages are saved milestones, not a time estimate.
⤺Service restart recovery: If a restart interrupts a submission in preparation, material retrieval, or grading, startup recovery resets it to the queued state so the worker can pick it up again.

Completed submissions end at 100%. A 429 cooldown may pause progress at 45% while the worker waits for provider capacity.
